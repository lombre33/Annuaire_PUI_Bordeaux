# Schéma Grist utilisé par le widget (extrait volontairement réduit)
#
# ATTENTION : ce fichier ne doit lister QUE les tables et colonnes effectivement
# lues par le widget (main.js / grist-data.js). Le document Grist source contient
# d'autres tables sans rapport avec ce widget (dont une table d'identifiants/session
# et une réplique d'un système d'authentification tiers) qui n'ont RIEN à faire ici,
# a fortiori dans un dépôt public. Si vous avez besoin du schéma complet pour du
# debug, gardez-le en local, jamais dans git.
#
# Version du schéma : table BDD (remplace l'ancienne table Annuaire, qui reste
# dans le document mais n'est plus lue).
#
# Le widget ÉCRIT dans deux tables, jamais dans une autre : BDD (la colonne
# Accepte_apparaitre, par l'interrupteur « Ma présence », et les colonnes de la fiche
# modifiables par « Modifier ma fiche » : prénom, nom, fonction, téléphone, rôle et
# listes de participations ; l'e-mail et l'établissement seulement quand un
# administrateur, mode admin allumé, modifie la fiche d'une autre personne) et
# Annuaire_Sonde (une ligne ajoutée puis supprimée à chaque chargement). Il lit aussi
# les métadonnées _grist_Tables et _grist_Tables_column pour écrire le téléphone dans la forme de sa
# colonne. Il ne crée ni ne modifie jamais une table ou une colonne : voir GRIST_SETUP.md
# pour les créer.
#
# Les logos (1.14.0) sont des pièces jointes du document : le widget lit les colonnes
# facultatives logo et ordre_bandeau d'Etablissements et la table facultative Financeurs,
# sans jamais y écrire. Pour afficher un fichier, il demande à Grist un jeton d'accès en
# lecture seule (getAccessToken, attachments.js).

Table BDD (table principale : une ligne par personne, lue par son nom via fetchTable)
  prenom, nom       : Text          OBLIGATOIRES (sans l'une d'elles, erreur explicite)
  Etablissement     : Reference(Etablissements)   OBLIGATOIRE
    Référence directe vers la ligne de l'établissement. Le widget n'utilise
    JAMAIS la colonne nom_de_domaine (règle du projet) : ni celle de BDD, ni
    celle d'Etablissements.
    Avec fetchTable, une Référence arrive normalement en identifiant de ligne
    (0 quand elle est vide). Les formes ['R', 'Etablissements', id] et « texte
    déjà résolu » restent tolérées : ne jamais supposer une seule forme pour
    une Référence. Voir refId() / refLabel() / etablissementFlags() dans
    grist-data.js.
  perimetre         : ReferenceList(REMMAPING_PERIMETRES_COMPETENCES)   OBLIGATOIRE
    Sert uniquement à savoir si le contact a au moins une valeur (cf. specs.md —
    « Nous n'afficherons QUE les contacts ayant au moins une valeur dans
    perimetre »). Le widget ne lit pas la table REMMAPING_PERIMETRES_COMPETENCES.
    Encodage brut renvoyé par l'API Grist pour les colonnes liste :
    ['L', id1, id2, ...] — une liste vide est donc ['L'] (longueur 1) et non [].
    Voir isInScope() / safeValues() dans grist-data.js.
  Accepte_apparaitre : Bool         OBLIGATOIRE (lue ET écrite par le widget)
    Accord de la personne pour figurer dans l'annuaire (cf. specs.md). Doit
    être une colonne de DONNÉES de type Bascule, pas une formule : Grist refuse
    d'écrire dans une colonne à formule, et l'interrupteur « Ma présence » en
    dépend. Seule la valeur vraie compte : vide, décochée ou autre valeur masque
    la personne. Sans cette colonne, le widget affiche une erreur au lieu
    d'afficher tout le monde. Voir hasAccepted() dans grist-data.js et
    setPresence() dans presence.js.
  Actions           : ReferenceList(Actions)
  Communautes       : ReferenceList(Communautes)
  Taches            : ReferenceList(Taches)
  Instances         : ReferenceList(INSTANCES)
  GT                : ReferenceList(GT)
  Competences       : ReferenceList(Competences)
  email             : Text          facultative
    Affichée sur la carte, et sert à retrouver la fiche de la personne connectée
    (comparaison sans casse ni espaces autour). Sans elle, le bandeau dit « Fiche
    introuvable » : la console le dit aussi. Voir createPeopleIndex() dans grist-data.js.
  Fonction          : Text          facultative

  Colonnes facultatives, rajoutées dans BDD sous ces noms : le widget les
  affiche quand elles existent, et s'en passe sinon.
  numero_de_telephone : Numeric     (téléphone de la carte ; le 0 initial qu'un
                                     type Numeric fait perdre est rétabli)
  Role_dans_le_PUI    : Reference(Role_Dans_le_PUI)   (tag « Rôle PUI »)

Tables de référence (id -> libellé, chargées via fetchTable)
  Chaque table porte un libellé brut (issu de l'import) et un libellé corrigé :
  le widget affiche le libellé corrigé quand il est rempli, le brut sinon.
  Actions            : Actions_corrigees (Choice)     puis Actions (Text)
  Taches             : Taches_corrige (Choice)        puis Taches (Text)
  Communautes        : communautes_corrigees (Text)   puis communautes (Text)
  GT                 : GT_corrige (Choice)            puis GT (Text)
  Competences        : Competences_corrigees (Text)   puis Competences (Text)
                       + Macro_competences (Text) : le domaine de chaque compétence.
                       Une même table, deux lectures : le libellé de détail
                       (les valeurs du menu « Compétences ») et Macro_competences
                       (les domaines, qui rangent ce menu en groupes).
                       Une compétence sans domaine renseigné est classée sous
                       « Autres » ; deux écritures d'un même domaine (casse,
                       accents) n'en font qu'un. Le widget n'utilise pas
                       BDD.Comptetences_macr : le domaine d'un contact se déduit
                       de ses BDD.Competences.
  INSTANCES          : Instances_Corrigees (Choice)   puis Instances (Text)
                       (le nom de la table est en majuscules)
  Etablissements     : acronyme (Text), nom_complet (Text),
                       fondateur (Bool), partenaire (Bool), autres (Bool),
                       ok_pour_apparaitre (Bool)
    Libellé = acronyme, avec repli sur nom_complet si acronyme est vide pour
    cette ligne (certaines lignes n'ont que nom_complet de renseigné — cause
    du bug "établissement invisible sur les cartes", cf. CHANGELOG).
    fondateur/partenaire/autres/ok_pour_apparaitre pilotent l'affichage des
    contacts de cet établissement (cf. specs.md) : seul un établissement
    fondateur OU partenaire, ET ayant validé (ok_pour_apparaitre = true),
    laisse voir ses contacts — "autres" n'est jamais affiché. Voir
    etablissementFlagsFromRows() / isEtablissementEligible() dans grist-data.js.
    Colonnes facultatives de l'habillage (1.14.0), lues par branding.js :
      logo          : Attachments   le logo de l'établissement, sur ses cartes et dans
                                    le bandeau du bas. Seul le premier fichier est affiché ;
                                    une cellule vide, ['L'] ou 0 n'a pas de logo (le nom
                                    s'affiche à la place). Une cellule « Pièces jointes » arrive
                                    sous la forme ['L', 12, 13] : des identifiants de fichiers.
      ordre_bandeau : Numeric       la place de l'établissement dans le bandeau du bas, de
                                    gauche à droite (1, 2, 3…). Seuls les fondateurs validés
                                    (fondateur ET ok_pour_apparaitre) y figurent ; sans numéro
                                    valable, ils passent après les autres, dans l'ordre de la table.
  Role_Dans_le_PUI   : Role (Text)

Table Financeurs (facultative, à créer dans Grist à la main, voir GRIST_SETUP.md ; lue, jamais écrite)
  nom   : Text         le nom du financeur : affiché à la place du logo quand le fichier manque,
                       et lu par les lecteurs d'écran. Le financeur dont le nom est « France 2030 »
                       (casse et accents ignorés) ferme aussi le bandeau du bas, sous la forme d'un rond
                       (BRANDING.roundelFunder dans constants.js).
  logo  : Attachments  le logo du financeur (le premier fichier)
  ordre : Numeric      l'ordre des logos en haut de la page, de gauche à droite (1, 2, 3…)
  Pas de table Financeurs : l'en-tête n'a simplement pas de financeurs, sans aucun message.
  Pourquoi une table : les financeurs ne sont pas des établissements, les ranger dans
  Etablissements les ferait apparaître dans le filtre « Établissement » et dans les règles de
  visibilité. Voir branding.js.

Table Annuaire_Sonde (à créer dans Grist, voir GRIST_SETUP.md ; vide au repos)
  Email : Text    formule de déclenchement `user.Email`, appliquée aux nouvelles
                  lignes : l'adresse de la personne qui a créé la ligne
  Admin : Bool    formule de déclenchement : vrai si cette adresse figure dans ACL
                  avec admin coché (casse et espaces ignorés)
  Le widget y ajoute une ligne à chaque chargement, la relit par son identifiant
  puis la supprime. Un compte Lecteur ne peut pas y écrire : il n'est pas
  identifié. Voir readIdentity() dans identity.js.

Table ACL (lue par la formule de Annuaire_Sonde.Admin, jamais par le widget lui-même)
  email : Text, Responsable_de_l_Etablissement : Reference(Etablissements),
  admin : Bool (donnée, à cocher pour les administrateurs)
